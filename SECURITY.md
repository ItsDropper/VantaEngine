# Security Policy

## Supported versions

Security fixes are currently targeted at the latest code on the `main` branch. There are no formal long-term-support releases yet.

## Reporting a vulnerability

Please do not publish exploit details in a public issue before maintainers have had a chance to assess the risk. Use GitHub's private vulnerability reporting feature for this repository if it is enabled. If private reporting is unavailable, contact the repository owner through their GitHub profile and provide only the minimum details needed to establish contact.

Include the affected commit/version, impact, prerequisites, and a minimal reproduction when safe. Do not include passwords, access tokens, private user data, or other secrets in reports.

## Scope and expectations

- Reports will be assessed on a best-effort basis; no response-time or bounty guarantee is implied.
- A fix should include regression coverage where practical.
- Security fixes should avoid exposing additional sensitive diagnostic data.
- Do not test against systems or data you do not own or have explicit permission to assess.

This policy describes the project's current process and does not imply that the software has undergone an independent security audit.
